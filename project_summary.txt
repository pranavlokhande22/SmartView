SMARTREVIEW: SYSTEM SUMMARY & ARCHITECTURAL DEEP-DIVE
===================================================

SmartReview is a privacy-preserving, local-first analytics application designed to ingest multi-application user reviews, preprocess textual content, predict sentiment using machine learning, extract critical negative themes, calculate issue severity, and present actionable developer recommendations through a dashboard.

This document provides a comprehensive analysis of the system architecture, algorithms, workflows, and technology stack of SmartReview.

--------------------------------------------------------------------------------
1. TECHNOLOGY STACK ANALYSIS
--------------------------------------------------------------------------------
* Programming Language: Python 3.10+ (Tested up to Python 3.14.3)
* User Interface Framework: NiceGUI 3.x
  - Provides a reactive front-end with dynamic Python-to-JS bindings.
  - Combines FastAPI, Uvicorn, TailwindCSS, and Quasar framework elements under the hood.
  - Features a custom dual-theme styling interface (light/dark modes) with smooth transitions, CSS typography enhancements (Outfit/Roboto fonts), and embedded interactive scripts.
* Database Layer: SQLite (Embedded)
  - Located at `database/reviews.db`.
  - Configured with Write-Ahead Logging (WAL) mode (`PRAGMA journal_mode = WAL`) and Normal synchronization (`PRAGMA synchronous = NORMAL`) to optimize high-concurrency read-write transactions.
  - Full relational integrity enforced via `PRAGMA foreign_keys = ON`.
* Core Data & Utilities: Pandas & NumPy
  - Used for large-scale dataset manipulation, data cleaning, and high-performance vector operations during batch ingestion.
* Machine Learning & Modeling: Scikit-Learn, Joblib
  - Feature extraction: TF-IDF vectorization.
  - Classifier: L2-Regularized Logistic Regression.
  - Serialization: Joblib for offline model persistence on disk.
* Natural Language Processing (NLP): NLTK (Natural Language Toolkit)
  - Leverages NLTK's `PorterStemmer` for suffix-stripping text cleaning.
  - Employs a local, offline stopword database to avoid internet connection dependencies.
* Visualizations & Charts: Apache ECharts & Matplotlib
  - High-performance, responsive interactive charts rendered in the browser using Quasar/ECharts integration.
  - Matplotlib operates in head-less mode (`Agg` backend) for background server-side image compilation and PNG report generation.
* File Parsing: OpenPyXL
  - Required for reading Excel spreadsheet formats (`.xlsx`, `.xls`) during review ingestion.

2. DATA PIPELINE & FUNCTIONAL WORKFLOW
--------------------------------------------------------------------------------
The SmartReview processing pipeline operates in five distinct stages:

[RAW DATA] CSV/Excel
    │
    ▼
1. INGESTION (Ingestion Engine) ──► Saves raw text & metadata in SQLite
    │
    ▼
2. PREPROCESSING (Text NLP)   ──► Cleans, tokenizes & stems text
    │
    ▼
3. CLASSIFICATION (ML Model)  ──► Predicts & stores sentiment labels
    │
    ▼
4. THEME EXTRACTION (NLP)     ──► Group negative reviews, compute severity
    │
    ▼
5. RECOMMENDATION & UI        ──► Renders interactive charts and exports reports

--- Stage 1: Data Ingestion ---
* Inputs: CSV or Excel spreadsheet files.
* Header Synonym Matching: Matches common column labels to normalize headers into standard keys:
  - `app_name`: app, appname, name, app_name
  - `review_text`: translated_review, content, text, review, review_body, comment
  - `rating`: rating, score, stars, star, user_rating
  - `review_date`: review_date, date, at, time, timestamp, posted_at, review_time
  - `app_version`: app_version, version, current_ver, version_name
* Validation: Drops empty records or those with review text shorter than 5 characters.
* Deduplication: Removes duplicate entries based on `review_text` + `app_name` + `review_date` to prevent skew.
* Database Write: Inserts newly mapped apps and reviews into SQLite using bulk `executemany` statements.

--- Stage 2: NLP Preprocessing ---
* RegEx Text Cleaning:
  - Converts text to lower case.
  - Strips URLs and hyper-links (`https?://\S+|www\.\S+`).
  - Removes Unicode emoji characters.
  - Filters out punctuation and numbers.
* Stopword Removal: Removes common connector words (e.g., 'the', 'and', 'with') using a local stopword set.
* Stemming: Reduces words to their base stem (e.g., 'crashing', 'crashed' -> 'crash') utilizing NLTK's Porter Stemmer algorithm.
* Persistence: Stores the cleaned text string and its token count in the `cleaned_reviews` database table.

--- Stage 3: Sentiment Classification Model ---
* Feature Extraction (TF-IDF):
  - Converts clean review text into numeric feature matrices using Term Frequency-Inverse Document Frequency.
  - The vectorizer is configured to extract unigrams and bigrams (`ngram_range=(1, 2)`) with a minimum document frequency boundary to prune noise.
* ML Classifier (Logistic Regression):
  - Train: Logistic Regression is fitted on the TF-IDF feature matrix. It uses a `balanced` class weight strategy to prevent skew in databases where positive reviews greatly outnumber negative ones.
  - Inference: Predicts sentiment class labels ('positive', 'neutral', 'negative') and extracts class probabilities to obtain confidence scores.
* Persistence: Serializes trained parameters (`tfidf_vectorizer.pkl` and `sentiment_model.pkl`) to `src/models/` for offline reuse. Saves inference labels and scores to `sentiment_results`.

--- Stage 4: Theme Extraction ---
* Sub-setting: Filters database reviews to isolate only those classified as `negative`.
* Word N-grams: Tokenizes the negative review text and builds word unigrams, bigrams, and trigrams.
* Keyword Matching: Maps phrases against defined vocabulary categories representing app bugs:
  - 'crash': crash, crashes, force close, hang, freeze, stop
  - 'battery': battery, drain, overheat, hot
  - 'login': login, signin, auth, otp, password
  - 'performance': lag, slow, latency, stutter, delay
  - 'ui': ui, interface, layout, screen, button
  - 'payment': payment, pay, upi, refund, transaction
  - 'notification': notification, notify, alert
  - 'ads': ad, ads, advertisement

--- Stage 5: Severity Scoring and Recommendation ---
* High-severity issues are prioritized based on a multi-dimensional severity scoring algorithm.
* Actionable, structured recommendations are mapped to each theme to guide developers (e.g. optimizing background sync for battery drain).
* Renders ECharts visualizations (Trend charts, heatmaps, pie charts) and allows data export.

3. CORE ALGORITHMS
--------------------------------------------------------------------------------

A. TF-IDF FEATURE EXTRACTION
TF-IDF calculates the relative importance of a term in a document compared to the entire corpus.
- Term Frequency (TF): Term frequency within a single review.
- Inverse Document Frequency (IDF): log(Total Documents / Documents containing the term).
- Feature Score: TF * IDF.
By using unigrams and bigrams, the vectorizer captures contextual phrases (e.g., "not work" or "crashes often") rather than just single words.

B. LOGISTIC REGRESSION WITH BALANCED WEIGHTING
Logistic Regression models the probability of a categorical sentiment outcome using a logistic sigmoid function.
Because app reviews are heavily skewed towards positive sentiment (typically 80-90% positive), standard training would result in a model biased toward positive classification.
To resolve this, the classifier computes weights inversely proportional to class frequencies:
  Weight(class_i) = Total_Samples / (Number_of_Classes * Count(class_i))
This penalizes misclassifying minority classes (e.g., negative reviews) more severely during optimization.

C. THEME SEVERITY SCORING ALGORITHM
Severity is determined by combining three parameters: frequency (how often an issue occurs), negativity (confirming it is indeed a complaint), and recency (how recently it started occurring).
The formula is:
  Severity = (0.5 * FrequencyScore) + (0.3 * NegativityScore) + (0.2 * RecencyScore)

Parameters:
1. FrequencyScore (Normalized to [0,1]):
   - Formula: F_theme / F_max_theme
   - Measures how common this theme is relative to the most common theme.
2. NegativityScore:
   - Evaluated as 1.0 (since the extraction runs on negative reviews).
3. RecencyScore (Scale [0,1]):
   - Formula: Count(Reviews posted within the last 30 days) / Total Reviews.
   - Measures how fresh or active the bug is. A fallback of 0.5 is assigned if no dates are available.
The combined score is scaled to 100% to rank issues on a severity leaderboard.

4. SYSTEM ARCHITECTURE & CODE MODULES
--------------------------------------------------------------------------------
* `main.py`: The entrypoint script. Initializes the database schemas and launches the NiceGUI server.
* `database/schema.sql`: Contains the DDL schemas establishing tables: `apps`, `reviews`, `cleaned_reviews`, `sentiment_results`, `recommendations`.
* `database/handler.py`: High-level wrapper for database connections, WAL pragmas, transactional operations, and batch writes.
* `src/ingestion.py`: Normalizes headers, validates contents, filters short reviews, deduplicates records, and imports Excel/CSV data.
* `src/preprocessing/preprocess.py`: Handles regex cleaning, stopword filtration, and word stemming.
* `src/classifier/sentiment_model.py`: Trains the TF-IDF and Logistic Regression classifiers, saves pkl models, and predicts batch sentiments.
* `src/theme_extractor.py`: Extracts unigrams/bigrams/trigrams, maps them to categories, scores them via the Severity formula, and stores recommendations.
* `src/exporter.py`: Generates downloads for CSV sentiment lists, recommendation reports, and renders Matplotlib chart PNG files.
* `src/ui/routes.py`: Registers page routes (`/`, `/dashboard`, `/reviews`, `/analytics`, `/docs`, `/features`, `/about`, `/contact`) and handles global styling.
* `src/ui/app.py`: Renders the main ingestion dashboard, pipeline runners, filters, Quasar table, and sentiment charts.
* `src/ui/analytics.py`: Renders the advanced analytics page, trend lines, correlation heatmaps, and severity leaderboard tables.

--------------------------------------------------------------------------------
5. PERFORMANCE & STORAGE METRICS
--------------------------------------------------------------------------------
Based on capacity and scalability testing, the system exhibits the following benchmarks:
- Database Insertion Rate: ~13,000 to 14,000 reviews/second.
- Database Storage Density: ~11,300 reviews per Megabyte (average review length 45 characters).
- Storage Capacity Predictions:
  * Small scale (500 MB database): Supports ~5,000,000 reviews.
  * Medium scale (1 GB database): Supports ~10,000,000 reviews.
  * Large scale (5 GB database): Supports ~50,000,000 reviews.
- Latency: Batch processing of 100,000 reviews is completed in approximately 9.3 seconds.
